Step 0 · Prerequisites

0a · Put the latest build on your iPhone (needed for Tests 2–4)

The iOS audio fix is native code, and the Pomodoro/Meds changes are web code bundled into the app — both only reach your phone after a rebuild.

cd /Users/kyledisch/Projects/stopwatch
npm run ios:open

Then in Xcode: pick your iPhone as the run destination (top bar) and press the ▶ Run button (or ⌘R). Wait for it to build and launch on the phone.

• Your running Pomodoro session will survive the rebuild (its state lives in the app’s storage and the timer catches up to the real clock on relaunch). Just don’t delete the app first — Build & Run over it.
• On a free Apple developer cert the app expires every 7 days; rebuilding re-signs it.
• If Xcode complains about “pods”, run cd ios/App && pod install then try again.
• Sanity check you’re on the right code: git status should show branch claude/timer-actions-dropdown-visible-eBi1u. If not: git checkout claude/timer-actions-dropdown-visible-eBi1u first.

Test 2 · iOS background ambient noise please verify

The brown/ambient noise used to stop the instant you switched away from Tempo, because iOS suspends the web view’s audio. The fix tells iOS this audio is allowed to keep playing in the background. This is the one I couldn’t test myself.

  1. Make sure you did Step 0a (new build is on the phone).
  2. Make sure the app is not muted (the sound/speaker toggle is on) and your phone’s ringer/volume is up.
  3. Go to Timers → Pomodoro. Tap Settings (in the row of links under the timer).
  4. Find “Ambient sound”, choose Brown, then tap Save.
  5. Press the big Start button to begin a work session. Confirm you can hear the brown noise.
  6. Now swipe up to the Home screen (or open another app, or lock the screen).
  7. Listen.
  8. Return to Tempo and confirm the session is still running normally.
Expected: the brown noise keeps playing after you leave Tempo and while the screen is locked. (Bonus: if you had music or a podcast playing, starting the noise should have paused it — that’s the intended “take over” behavior.)
If it fails (noise goes silent the moment Tempo is backgrounded): note that down and tell me. The next step would be a small native plugin to explicitly grab the audio session when the noise starts.
You can also try this from Timers → Flow — the Flow setup screen has its own “Ambient sound” dropdown. The noise plays during the focus block.

Test 3 · Pomodoro “Actions” menu shows while idle verified in browser

Previously the “Actions” link only appeared while a Pomodoro was running. It now appears in the idle (not-started) state too.

  1. Go to Timers → Pomodoro with the timer idle (showing the green Start button, not a running countdown). If one is running, that’s fine too — but the point of this test is the idle state.
  2. Look at the row of links near the bottom: Stats · Settings · Actions · Auto: Off · Saved Tasks.
  3. Confirm “Actions” is present even though nothing is running.
  4. Confirm all five links sit on one line and are not hidden behind the bottom tab bar (Timers / Wellness / Rhythm / Analytics).
  5. Tap Actions. A panel should open with: Clear Focus Goals, Clear Break Tasks, Restart Phase, Finish & Reset, Clear All Tasks — and stay open while idle.
Expected: “Actions” is visible and tappable while idle; the link row is fully readable above the tab bar; the Actions panel opens and stays open.
The “Auto-advance: Off” label was shortened to “Auto: Off” so all five links fit on one line — that’s intentional.

Test 4 · Meds prescription supply counter (opt-in) verified in browser

You can now track how many pills are left in a prescription. It’s opt-in per medication, so only meds you switch it on for show the counter.

  1. Go to Wellness → Meds.
  2. Tap + Add. Enter a name (e.g. “Test Med”). Check the box “Track prescription supply”.
  3. Confirm a “Pills per prescription” field appears (defaults to 30). Leave it at 30 and tap Save.
  4. On that med’s card, confirm a green badge reads “30 left · of 30 · since today” and there’s a “New prescription” button.
  5. Confirm your other meds (where you didn’t check the box) show no badge and no “New prescription” button.
  6. Tap “Took it now” on the test med. The badge should drop to “29 left.”
  7. Tap “New prescription,” change the number to 3, tap Save count. The badge should read “3 left” and turn amber/orange (low warning).
  8. Tap “Took it now” three more times until it reads “0 left” — it should turn red (empty).
  9. Tap the pencil (edit) on the test med, uncheck “Track prescription supply,” and Save. The badge and “New prescription” button should disappear.
  10. Optional cleanup: delete the test med (the × on its card).
Expected: only the opted-in med shows the supply UI; the count decrements on each dose; amber at ≤5 left, red at 0; unchecking the box removes the supply UI.

Known issue — no action needed

iOS “Sign out” doesn’t fully sign out. In Settings (gear icon) → Cloud Sync, tapping “Sign out” may still leave you signed in on iPhone (it works fine on the web). This is a previously known bug, already tracked — not something these changes touched. If it ever gets in your way, the workaround is to toggle “Enable cloud sync” off in that same panel. No need to test it.
