## Goal

Land the offline buffer + `Platform.network` shim so that ops authored during offline windows persist across tab close, drain FIFO on reconnect, and preserve original wall-clock timestamps captured at user-action time (strategy doc Q3 lock at `docs/CLOUD-SYNC-STRATEGY.md:116`). The buffer is a pointer-based queue (one entry per dirty record per store) in a new `tempo_sync_db` IDB database; compaction for per-field-LWW stores keeps the queue bounded under chatty UX; `PENDING_OP_CAP = 1000` immutable cap drops the oldest with a visible toast on overflow. The Platform.network shim activates the dormant feature-detect hooks already living in `js/sync-engine.js:1911-1942` (steady-state pause-on-offline + resume-on-online) as a retroactive bonus.

## Risks

| Risk | Likelihood | Blast radius | Mitigation |
|------|------------|--------------|------------|
| **IDB upgrade failure on first-load post-merge (broken IDB / quota exceeded / Private Browsing mode)** | low | local-only (low — buffer dormant; steady-state polling still works on reconnect within 30s) | Opening a brand-new IDB DB (`tempo_sync_db v1`) can fail on: (a) Safari Private Browsing (IDB requests reject); (b) Firefox enhanced tracking protection on first-party with reduced quota; (c) iOS WebView with the user disabling site data in Settings → Safari → Privacy. **Mitigation:** every `SyncBuffer.enqueue` / `SyncBuffer.drain` call wraps the `_open()` promise in a try/catch + log once via `console.warn`; on failure, return `{ ok: false, kind: 'idb-unavailable' }` and bail. The local-first contract preserves correctness — local writes hit localStorage / `stopwatch_history_db` regardless of the buffer's availability. Test case (sync-buffer #14) verifies the `_open()` failure path returns a clean error without throwing. Document in Manual setup steps that users in Private Browsing won't get the offline-replay optimization but will continue to get steady-state polling. |
| **Offline detection false-positive on flaky Wi-Fi (`navigator.onLine === false` when actually online)** | med | local-only (low — false negative just delays the steady-state cycle by one 30s tick) | `navigator.onLine` is famously unreliable across browsers — Firefox / Chrome / Safari each have their own quirks (e.g., Chrome reports `false` when Wi-Fi is connected but no DNS works; Safari sometimes reports `true` while the radio is off). **Mitigation:** the dispatcher's `_maybeBufferOnOffline` helper is the gate; if `Platform.network.isOnline() === false` triggers spuriously, the worst outcome is a few extra buffer entries that drain on the next `online` event (or on the next steady-state cycle, since `_runMergeCycle` runs on the 30s tick regardless of `isOnline()`'s value). The local record is already written to localStorage / IDB before the dispatcher fires, so user-facing correctness is preserved. Document the known quirk in the sign-off checklist. Test case (sync-buffer #11) verifies that a spurious offline → online flicker results in a single drain pass without duplicates (compaction by `(store, recordId)` collapses repeated enqueues). |
| **Drain mid-cycle conflict with steady-state merge tick (drain + merge cycle racing)** | low | data-correctness (low — F13 gate coordinates) | When `online` fires, two paths can trigger a merge cycle simultaneously: (a) the existing 1911-1942 hook resumes the steady-state timer, which fires `_runMergeCycle` on the next tick; (b) the new drain trigger calls `SyncBuffer.drain()` which routes through the per-store merge fns directly. Both paths hit the same CAS-level locks on Firestore — Firestore transactions handle the race, but on the client side two concurrent merge cycles could double the read budget for one cycle. **Mitigation:** `SyncBuffer.drain()` and `_runMergeCycle` are NOT mutually-exclusive at the code level — both call the same per-store merge fns. The per-merge-fn body is idempotent (E-1c/d/e tests verify this); a race condition produces at most a transient `tx.refuseWriteback` on the loser, which is already handled by the existing per-record try/catch.
