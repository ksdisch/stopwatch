## Goal

Land the milestone PR that flips steady-state cloud sync from "dormant behind dev flag" to "default-on for any user with the master flag set." The two remaining throwing stubs become real merge functions: `js/sync-merge-rest-log.js` does per-day sleep LWW by `updatedAt` + naps append-merge dedup by `(deviceId, startedAt)` (one Firestore doc per `YYYY-MM-DD` key), and `js/sync-merge-presets.js` does full-record LWW by `(id, updatedAt)` with tombstone propagation (`deletedAt` field on each preset record — a soft delete that propagates both directions via CAS writeback). `js/presets.js` is rewritten on three fronts: `Presets.remove(id)` no longer hard-filters but sets `target.deletedAt = Date.now()` + `Schema.stamp(target)` + `saveAll(presets)`; `Presets.getAll()` filters tombstones via `.filter(p => p.deletedAt == null)` so the UI never sees deleted records; a sibling `Presets._getAllIncludingTombstones()` is added so `snapshotForSync()` continues propagating tombstones to cloud. `js/recovery-ui.js` gains `Schema.stamp(sleep)` at the `setSleep` site and `Schema.stamp(nap)` at the `addNap` site — today's writes have no envelope, so the new merge functions need stamps for LWW + dedup to work. `js/sync-engine.js` gets three surgical edits: a new `_filterFutureRecordsInSnapshot(key, snapshot)` helper at the dispatcher level that walks the snapshot's payload, identifies which inner field holds the records per store key, filters records whose `schemaVersion > Schema.SCHEMA_VERSION`, and logs skip counts for observability (existing per-merge-fn cloud-side gates STAY — two layers, different vectors per Pick C on TODO #4); the `STEADY_STATE_ENABLED_KEY` constant + `_isSteadyStateEnabled()` function + the gate check at line 1689 are deleted (Pick A on TODO #5); and a new `_maybeAutoStartSteady(user)` helper gates on all 4 conditions and is called from both `init()` end and `_maybeAutoHydrate()`'s `.then()` (Pick C on TODO #6). Two new test files cover the per-store merges plus the existing `tests/sync-engine.test.js` extends with dispatcher gate + auto-invoke + flag-removal regression cases, pushing the baseline from 501 to approximately 519-541.

## Risks

| Risk | Likelihood | Blast radius | Mitigation |
|------|------------|--------------|------------|
| **Sleep LWW updatedAt missing on existing records — comparison crashes or wins randomly** | med | data-correctness (med — pre-E-1e sleep entries silently lose to anything stamped) | Pre-E-1e sleep entries have no envelope stamp. The cloud-side has no `updatedAt` to compare; the local-side has none either after pre-E-1e migration data lands in cloud. Naive comparison `cloudAt > localAt` evaluates `undefined > undefined === false`, falling through to "local wins" silently. **Mitigation:** treat absent `updatedAt` as `-Infinity` so the side WITH a stamp always wins (`(cloudAt || -Infinity) >= (localAt || -Infinity)`), and the next write on the unstamped side gets the stamp lazily via the new `Schema.stamp(sleep)` at `setSleep`. Test case (rest_log #4 + #5) verifies both directions. |
| **Naps without deviceId — dedup key collides across devices** | low | data-loss (low — two devices logging naps at the same `startedAt` are merged as one) | Pre-E-1e naps have shape `{startedAt, durationMs, endedEarly?}` — no `deviceId`. Two devices logging naps at the same `startedAt` (vanishingly unlikely with millisecond precision, but technically possible) would dedup as one. **Mitigation:** (1) Backfill `deviceId = History.getDeviceId()` at first save post-E-1e in `addNap`'s rewrite. Pre-E-1e naps stay without `deviceId` until next save; the merge function's fallback sig `'no-device@' + startedAt` collapses them by `startedAt` alone (acceptable — pre-E-1e the user only had one device anyway). (2) Document the backfill in the audit + sign-off checklist. (3) Test case (rest_log #7) verifies the fallback path. |
| **`Presets.remove` becoming tombstone-set breaks existing delete UX semantics** | low | data-correctness (low — storage grows unboundedly with deletes; UI hides tombstones correctly) | Today the delete UI button calls `Presets.remove` which hard-deletes.
