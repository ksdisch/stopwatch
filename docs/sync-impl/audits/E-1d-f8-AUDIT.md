## Goal

Land F8 distraction sessionId-keyed migration end-to-end in one PR: a new `js/distractions.js` module owns both consolidated `flow_distractions` + `pomodoro_distractions` localStorage stores under their existing key names but reshaped from flat arrays into sessionId-keyed maps (`{ [sessionId]: [entries] }`), a phased one-way migration converts legacy flat arrays into the new map shape by attaching them to the currently-active session's sessionId (or to a synthetic `'pre-migration-orphan'` key when no session is running), every write is stamped via `Schema.stamp(entry)` (F10) and gated through `SyncState.canWrite()` (F13), and the migration marker `tempo_distractions_migration_v1='1'` guarantees idempotency across re-boots. UI surfaces in `js/flow-ui.js` + `js/pomodoro-ui.js` switch reads from `loadFlowDistractions()` / `loadDistractions()` to `Distractions.getForSession(context, sessionId)` filtered by `Flow.getSessionStartedAt()` / `Pomodoro.getSessionStartedAt()`, and every `saveFlowDistractions([])` / `saveDistractions([])` reset becomes `Distractions.clearSession(context, sessionId)` so a session reset drops only that session's map entry (no tombstones needed — implicit-delete-on-reset). `js/persistence.js` line 67's app-mode-change `removeItem('pomodoro_distractions')` becomes a clear-all-pomodoro-sessions helper. Sync wiring lands at the same time per Pick A on TODO #5 — `distractions` becomes the 6th `SYNCED_STORES` entry and a new `js/sync-merge-distractions.js` ships per-session merge logic: cloud + local maps merge by sessionId, and within each session entries union + dedup by `(deviceId, timestamp)`. Two new test files cover the surface — `tests/distractions.test.js` for migration + module API and `tests/sync-merge-distractions.test.js` for the per-store merge — pushing the baseline from 476 to ~494-502.

## Risks

| Risk | Likelihood | Blast radius | Mitigation |
|------|------------|--------------|------------|
| **Migration corrupts in-flight distraction data — entries from an active session land under the wrong sessionId** | med | data-loss (med — the active session's existing distractions disappear from the UI summary) | If migration runs while a Flow / Pomo session is mid-flight, the legacy flat array contains entries for THAT session. `Flow.getSessionStartedAt()` returns the active session timestamp, so the array gets attached to the right key. **But:** if engine loadState recovery hasn't completed yet by the time `distractions.js` IIFE runs (script order matters — `flow.js` loads before `distractions.js` per the index.html plan, and engine loadState executes during the engine IIFE at line 79-86, BEFORE `distractions.js` runs), the accessor returns the recovered sessionStartedAt correctly. **Mitigation:** (1) per-entry try/catch in the migration union step (bad legacy entry shape MUST NOT abort the whole migration; matches E-1d-f3 Risk #1's mitigation). (2) Migration code reads `Flow.getSessionStartedAt()` via `typeof`-guarded call (`if (typeof Flow !== 'undefined' && typeof Flow.getSessionStartedAt === 'function')`) so test contexts that omit engines don't crash — they fall through to the orphan-key fallback. (3) Test case `migration attaches legacy array to active session if running` codifies. |
| **Migration runs twice and creates duplicates** | med | data-correctness (high — analytics + summary double-counts distractions per session) | If the marker write fails (storage quota, browser eviction) between the new-map write and `setItem(marker)`, the next boot re-runs. Re-reading the legacy keys (still on disk per Pick B) PLUS the already-written map could produce duplicates. **Mitigation:** write the new map FIRST, then the marker; the migration's defensive shape detection (already-map vs flat-array) reads the CURRENT key value before overwriting — if it's already a map, dedup-merge against legacy-transformed entries by `(deviceId, timestamp)` produces byte-identical output. Test case `migration idempotency — re-run produces identical output` codifies. |
| **UI clear sites left un-updated — stale data accumulates in the map** | med | data-correctness (med — sessions show distractions from prior sessions in their summaries; history records get bogus distractions persisted) | 5 Flow clear sites (lines 168, 214, 231, 276, 283) + 3 Pomo clear sites (lines 202, 272, 1165) each call `saveFlowDistractions([])` / `saveDistractions([])` today. Failure to convert any one to `Distractions.clearSession(context, sessionId)` would leave that session's entries in the map AND the next session would inherit them via `getForSession(currentSessionId)` only if the sessionIds collide (low chance with `Date.now()` precision), so the real failure mode is: the OLD session's map entry never gets dropped, occupying storage forever. **Mitigation:** (1) sign-off checklist row enumerates all 8 sites explicitly (5 flow + 3 pomo). (2) Test case `clearSession drops one session's entries without touching others` codifies. (3) Phase 4 ui-wirer visual verification: complete a session → reset → verify localStorage map no longer contains the dropped sessionId key. (4) Defensive monthly cleanup is NOT in scope for this PR but is a backlog item if accumulation becomes a real problem. |
