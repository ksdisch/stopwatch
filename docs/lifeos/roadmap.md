# Tempo Life-OS — Roadmap

**Status:** Approved · **Date:** 2026-06-08

A **phased, explicitly multi-session** build sequence. Each phase is sized to be **its own build session** and
ends at a concrete **gate** that must pass before the next phase begins. Build later — this document does not
authorize implementation; it sequences it.

**Suggested build mode:** hand each phase to a fresh session as a `/batch` run or an ultracode workflow. Phases
are ordered to deliver a **thin vertical slice early** (a real recap on the phone by P1) and to prove the
**federation pattern** before scaling it (P2 → P4).

Maturity context from discovery: Tempo evolves into the trunk; `personal-health-elt` already publishes its feed;
`learning-hub` is a working app to federate; Chickens/Life Building/Relationships need real building.

---

## Phase 0 — Foundations (umbrella + contracts + harness) — ✅ Gate passed 2026-06-08

**Goal:** stand up the trunk and the spine plumbing — nothing user-facing yet.
**Key tasks:**
- Evolve the `stopwatch` repo into the `life-os` trunk (in place; keep the 918 tests + sync intact).
- Define the **Firestore contracts**: the synthesis-record schema and the pillar-feed/mart schema
  (`architecture.md` §3, §7).
- Port the **council scheduling harness** from `job-search-mas` (launchd template, run-wrapper, PATH preflight,
  Slack/SMS failure alerts).
**Gate:** a scheduled launchd job writes a dummy synthesis record to Firestore and the PWA reads it back on the
phone; failure alert fires on a forced error.
**Draws on:** `architecture.md`, `decisions/0001`, `0003`, `0005`.

## Phase 1 — Home synthesizer + bubble map (vertical slice)

**Goal:** the home experience, end to end, over seed data.
**Key tasks:**
- Build the **Home hub**: bubble map (3 toggleable lenses + default) as the hero, synthesis cards + "this week's
  3 moves" below.
- Build the **Home Synthesizer** archetype + the **Balance engine** (`Importance × Neglect`) reading pillar
  records; daily-glance + weekly-recap jobs.
- Seed mock pillar records to drive it.
**Gate:** a real weekly **Balance recap** renders on Kyle's phone, generated by a local council from pillar
records; bubble map flexes off Balance.
**Draws on:** `architecture.md` §3–4, `decisions/0004`, `0005`.

## Phase 2 — Physicals (first real pillar, end to end)

**Goal:** replace seed data with one real, federated pillar — proving the contract path.
**Key tasks:**
- Consume `personal-health-elt`'s `recovery_state` mart as the Physicals Module.
- Build the **Physicals hub** + Areas (Recovery, Training load, Sleep, Meds) + the pillar synthesizer; set initial
  **targets** so `Neglect` is meaningful.
**Gate:** Physicals contributes a **real normalized score** into Balance + the bubble map, sourced from the
published mart (not mock data).
**Draws on:** `pillars.md` §2, `integration-plan.md` §5, `data-sources.md`.

## Phase 3 — Chickens (the build-heavy native pillar)

**Goal:** the pillar that needs new capture, end to end.
**Key tasks:**
- Build **mood/affect capture** (the Tier-2 gap) in Tempo.
- Wire existing BFRB / Flow / Mindful engines into the **Chickens hub** + synthesizer; add the weekly Tier-3
  reflection (Capturer archetype).
**Gate:** Chickens produces a real score and a **stress nudge fires** (e.g. BFRB-up + sleep-down → a suggested
mindful session).
**Draws on:** `pillars.md` §3, `data-sources.md`.

## Phase 4 — Federate Growth + Career

**Goal:** prove federation **at scale** (two more pillars, via published feeds, with minimal new UI).
**Key tasks:**
- `learning-hub` publishes a **Growth summary** mart; the home shows a Growth bubble + card and **deep-links** in.
- `job-search-mas` publishes **career state**; surface it in Life Building → Career.
**Gate:** two federated pillars appear on the home map and feed Balance **purely through published marts**
(the federation pattern is now demonstrated three times: health-elt, learning-hub, mas).
**Draws on:** `decisions/0007`, `integration-plan.md`.

## Phase 5 — Life Building + Relationships (the two new native pillars)

**Goal:** complete the five-pillar set.
**Key tasks:**
- **Life Building**: Values/Goals capture, habit tracking (reuse Tempo), manual Finance metrics, Admin feed
  (Todoist + calendar), and the sub-hub synthesizers.
- **Relationships**: the "people I tend" list + **context cards** (concierge surfacing), the DogHood feed ingest,
  and the weekly reflection.
**Gate:** **all five pillars live**; a full cross-pillar Balance recap with every pillar contributing a real
score.
**Draws on:** `pillars.md` §1, §4, `data-sources.md`.

## Phase 6 — New-unit lifecycle + archetype library + hygiene

**Goal:** make the system **extensible and self-cleaning**.
**Key tasks:**
- Implement the **light add-gate** workflow (classify → spec → scaffold) and the reusable **archetype library**.
- Implement the **hygiene sweep** (adapt `trim-context`; weekly light / monthly deep; archive-not-delete).
**Gate:** Kyle can add a new **Area** via the workflow end to end, and a hygiene sweep archives a stale unit on
schedule.
**Draws on:** `decisions/0006`, `architecture.md` §5–6.

## Phase 7 — Feedback loop + polish

**Goal:** the modest self-improving layer.
**Key tasks:**
- **Nudge-efficacy learning** (track nudge → outcome; auto-tune wording/timing).
- **Weight-change proposals** (council proposes Importance/target changes for one-tap approval).
- Refine targets, copy, and the bubble-map lenses.
**Gate:** the council **proposes a weight change** (Kyle approves) and demonstrably **learns from a nudge
outcome**.
**Draws on:** `decisions/0004`.

## Deferred (post-v1)

Tracked in `open-questions.md`: remote/on-demand AI (a `claude` server sidecar or thin backend so synthesis can be
triggered/queried from the phone), a finance aggregator (Plaid), deeper personal-CRM features. Pick up only after
the five pillars are live and the local-first loop is proven.

---

## Gate discipline

No phase starts until the prior gate passes. If a gate reveals a wrong assumption, update the relevant ADR / doc
**before** proceeding — the plan is allowed to change; silently building past a broken gate is not.
