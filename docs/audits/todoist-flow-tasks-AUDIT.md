# todoist-flow-tasks · Flow Block user-task list + two-way Todoist integration (backlog follow-up A)

## Goal
Add a user-editable "Tasks for this block" list to the Flow Block — alongside the fixed pre-block ritual checklist — with the same two-way Todoist surface Pomodoro got in V1 (import via the shared picker, check/uncheck/create write-back, delete stays local). Reuses the shipped `js/todoist.js` engine + `js/todoist-ui.js` picker unchanged; the new UI logic lives in `js/flow-ui.js`, and (per RATIFIED DECISION 8) a small data-only allowlist edit lands in `js/export.js` for backup parity with Pomo.

## Blast radius
**Tier:** medium

**Justification:** The rubric's medium triggers fire on three counts — a new persistence key (`flow_user_tasks`), new CSS classes for the task-list section, and a mandatory `sw.js` cache bump (cached web files change). The PR touches **5 files** (`js/flow-ui.js`, `index.html`, `css/styles.css`, `sw.js`, and — per DECISION 8 — `js/export.js`). It is *not* high: no engine `js/<name>.js` module gains real logic, no new module is added (no new `<script>` tag), no `SYNCED_STORES` / `js/schema.js` / `js/platform.js` / Firebase / `ios/*` / `package.json` change, and no migration of an existing key (`flow_user_tasks` is brand-new). The `js/export.js` change is a single additive allowlist entry plus broadening one existing `if`-condition to reuse the already-shipped `_stripTodoistLinkage` stripper — no new logic, no new module, no sync/schema/native surface — so it does not lift the tier. The brief proposed medium; the rubric independently confirms medium. (V1 `bl-2-todoist` was high because it shipped 2 new modules, 4 keys, an engine, a network surface, and a shape migration — none of which recur here.)

## Manual setup steps
**Manual setup required: yes** — the user must supply a personal Todoist API token (free, generated at `todoist.com/app/settings/integrations/developer`) and paste it into the Tempo settings drawer (the V1 Todoist section) before any import / write-back smoke step. Token is device-local; re-paste on each device. The smoke plan in the brief is the canonical verification list; the high-value subset:

1. **Setup list renders.** `#/flow` idle → "Tasks for this block" section shows below the ritual checklist; empty state reads cleanly.
2. **Add + check local task (no token).** Type + Enter → row appears; toggling checkbox updates the row; no network, no errors.
3. **Import from Todoist** (token configured) → picker lists filter tasks → multi-select → tasks land in the Flow list (no dupes on re-import).
4. **Write-back close/reopen.** Check an imported task → it closes in Todoist; uncheck → it reopens.
5. **Create write-back.** Add a task with a token set → appears in Todoist's default project; the local row gets its `todoistId` stamped (re-import doesn't duplicate).
6. **Delete guard.** Delete an imported task in Flow → it REMAINS in Todoist.
7. **Start gating unaffected** (DECISION 2). Start enables on ritual-checklist completion regardless of the task list.
8. **In-session list** (DECISION 3). Start a block → running view shows the checkable list + "Tasks: N/M done"; checking one updates the count + closes in Todoist.
9. **`done` reset on new block** (DECISION 5). Complete some tasks, end/reset, start a new block → list text persists, all unchecked.
10. **Summary card** (DECISION 4). End a block → summary shows a "Tasks N/M" row.
11. **Offline write.** Disconnect → check a task → no UI error → reconnect → queue drains → Todoist task closes.
12. **Backup parity** (DECISION 8). Export a backup with at least one imported (linked) Flow task → open the downloaded JSON → confirm `settings.flow_user_tasks` is present with `text` + `done` but NO `todoistId` / `localTag` → clear state / import the backup on a fresh state → the Flow tasks reappear (unlinked) → confirm `flow_user_tasks` is NOT in the Firestore upload payload (it is not a `SYNCED_STORES` entry).
13. **No regression.** Ritual checklist + distraction log + recovery flow + Pomo saved-tasks (V1) all still work.
14. **(iOS, optional.)** One create + one close on device (re-paste token).
