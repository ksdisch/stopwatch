# live-activities-timer-mvp · Scaffold iOS Live Activities pipeline end-to-end for Timer mode (lock-screen + Dynamic Island)

## Goal
Land the foundational PR for backlog #3/#9 — add a custom Capacitor plugin (Swift) + Widget Extension Xcode target (SwiftUI) + `Platform.liveActivity` JS bridge that fires from the Timer engine, so a running countdown renders on the iOS lock-screen + Dynamic Island with OS-driven ticking. Web bytes stay equivalent; Stopwatch / Pomodoro / Flow / Interval / Cooking integrations defer to follow-up PRs.

## Blast radius
**Tier:** high

**Justification:** Four independent HIGH-tier drivers compound: (1) new Xcode target (`TempoLiveActivityWidget`) restructures `ios/App/App.xcodeproj/project.pbxproj`; (2) first **custom** Capacitor plugin in the repo — precedent-setting Swift + Obj-C-bridge surface; (3) `js/platform.js` extension adds a new native-branch namespace (`Platform.liveActivity`); (4) `ios/App/App/Info.plist` modification touches the production iOS bundle manifest. Compounded by `sw.js` CACHE_NAME bump + new persistence key (`live_activities_enabled`) + engine-layer touch (`js/timer.js`) + harness-precedent test addition. Per the system-prompt rubric, ANY of these alone would trigger high; this PR has four simultaneously. Orchestrator should PAUSE for explicit "ship it" before Phase 5 push.

## Manual setup steps

This PR cannot ship without iOS device validation. Web smoke is also required for regression check. Steps follow the brief's 16-step plan verbatim:

1. After all code commits land, run `npm run sync-www && npx cap sync ios && npm run ios:open`. The `cap sync ios` step MUST run before `ios:open` — without it the new Widget Extension target's plist + bundle won't ship into the iOS bundle.
2. In Xcode, select the Tempo target (NOT the Widget Extension target) + a real iPhone destination. Build + Run. Confirm app launches without crash AND Settings drawer shows new "Live Activities" section with ON toggle (when on a Capacitor build; web build must NOT show the section).
3. Navigate to `#/timers/timer`. Set a 1-minute countdown. Tap Start. Lock the phone (side button).
4. **Lock-screen check:** wake the phone (don't unlock). Confirm Live Activity appears with timer name (or "Timer" default), live-counting-down time display, Tempo's brand color accent. Countdown ticks at OS-level refresh (~1 Hz, Apple-managed).
5. Unlock briefly, lock again. Confirm activity is still showing (didn't get killed by lock-unlock cycle).
6. (Dynamic Island device only — iPhone 14 Pro+) Confirm compact pill near camera cutout shows countdown (trailing) + Tempo glyph (leading). Long-press the pill — confirm expanded view rolls down with timer name + larger countdown + progress bar + "Tap to open" affordance. Tap the expanded view — confirm Tempo opens AND routes to `#/timers/timer` (verifies the `tempo://` deep-link).
7. Wait for timer to finish. Confirm: existing alarm sound + vibration fire (no regression) AND Live Activity disappears within ~1 second.
8. Start another 1-minute timer. After ~10 seconds, tap Pause inside the app. Confirm Live Activity countdown freezes (does not keep counting down on lock screen).
9. Tap Resume. Confirm countdown resumes from the paused remaining time, not from the original duration. **Critical — confirm only ONE activity is visible** (no duplicates from the resume's re-call of `startTimer`).
10. Tap Reset. Confirm Live Activity disappears immediately.
11. Open Settings drawer (gear icon). Toggle "Live Activities" to OFF. Start a new timer. Confirm NO Live Activity appears (lock screen + Dynamic Island both empty). Also confirm any in-flight activity disappears immediately when the toggle flips OFF (the `endAll()` call fires).
12. Toggle Live Activities back ON. Start a new timer. Confirm activity appears.
13. Start a 1-minute timer. Force-quit Tempo (swipe up from bottom, swipe Tempo away). Confirm Live Activity continues showing the countdown (Apple keeps activities alive up to 8 hours after app exits — `endsAt` enables OS-local rendering). If activity vanishes within seconds, see Risks → "background mode entitlement" — likely needs to be added to `App.entitlements`.
14. Re-open Tempo. Confirm Timer engine's reconstructed state matches the lock-screen activity (same remaining time displayed in-app + on activity). No spurious second activity created.
15. Lock phone with timer running. From a different app, tap Live Activity on lock screen → confirm Tempo opens AND lands on `#/timers/timer` (not on default Stopwatch screen). Validates `tempo://` URL scheme + Info.plist registration + `appUrlOpen` JS listener end-to-end.
16. **Web smoke (regression check):** in desktop browser, navigate to `#/timers/timer`, start a timer, confirm normal behavior (no console errors, no settings-drawer "Live Activities" section visible). Open settings drawer — confirm only existing items (Theme, Sound, Presets, Log past session, Focus mode, BFRB volume, Ambient sound, Cloud Sync) are visible. Live Activities section must NOT appear on web.
